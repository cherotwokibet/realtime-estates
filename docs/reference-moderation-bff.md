23 October 2026. Independently authored synthetic candidate. These modules are **not mounted as Next routes or a reviewer screen**. No current preview, default schema, production startup, vendor resource or old live system was changed or enabled.

Read admin `AGENTS.md` and the installed Next 16.4.2 route-handler and server/client guides before implementation. Added:

- `reference-moderation-server.ts`: server-only handler requiring development, synthetic preview, existing reference draft flag and separate `STAFF_PREVIEW_REFERENCE_MODERATION=synthetic-reference-transition-v1`. It uses the existing exact loopback host/instance/origin policy; caller bearer/context overrides are rejected. Every accepted request obtains fresh API-bound company/actor context before comparing browser stale-session headers.
- `reference-moderation-client.ts`: no-bearer browser adapter with captured instance/company/actor/listing/revision scope, strict original command/catalogue validation and exact original receipt comparison. One transition call sends one POST; explicit recovery posts the original private body to the BFF, which uses **only upstream GET**. Private content and reasons never enter URLs. The client cancels a late response after caller abort and bounds hostile bodies without awaiting an uncooperative cancel callback.
- `reference-moderation-wire.ts`: 128 KiB fatal-UTF-8/exact-length/no-encoding reader, decoded duplicate-key and integer-token checks for revisions, money, ordered-photo positions, publication pointer and room counts. The existing reference reader now accepts an optional parser; its default behavior is unchanged.

Prepared BFF operation paths are `/api/staff/listings/{id}/reference-transition-operations/{operationId}` and the same path with `/recover`, both POST. Versioned read paths are `/api/staff/{listings|reviews}/{id}/reference-revisions/{revision}/{expectedVersion}/{catalogueVersion}`, GET. The last path segment is an exact historical catalogue hint: the BFF fetches that stored catalogue and the SDK checks it against the actual revision attributes and editorial version. A wrong/current catalogue cannot relabel a saved revision; it fails closed. It supplies no tenant, actor or role authority. The future initial screen loader still needs a server-bound way to discover the saved catalogue version; this checkpoint does not claim that loader exists.

The browser adapter exposes `catalogue`, `read`, `transition` and `recover`. Fresh server context and current API/SQL role/assignment remain the authority. Complete historical review facts and actor-bound receipt outcomes are validated on both sides. Write response loss or corruption remains uncertain. A known rejected write is explicit; recovery failure remains a failed read and must not clear an existing controller's uncertainty. The tab-scoped retained-original store/controller and UI that enforce that final rule remain next. No automatic replay, replacement command, persistent bearer or browser-selected upstream authority is introduced.
