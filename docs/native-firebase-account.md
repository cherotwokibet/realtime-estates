# Native Firebase account mode

Checkpoint462, 19 November2026. The default mobile build remains the existing preview. The new native account screen is an explicit account-only mode; it does not connect hosted identity to the synthetic property catalogue. A reviewed public Firebase-authorized customer gateway and a verified account with an active company binding are required. A private Cloud Run endpoint protected with a service IAM audience is not such a gateway. Do not put a service identity/key in the app to reach it.

## Configuration and flow

Set MOBILE_FIREBASE_CUSTOMER_CONFIG only for a controlled build, as a JSON object with exactly mode, tenantId, apiOrigin and firebase. mode is firebase-native-customer-v1. tenantId is the trusted company UUID; apiOrigin is the exact reviewed HTTPS customer-gateway origin without a trailing slash, path, query, fragment or credentials. firebase has exactly apiKey, projectId, authDomain and appId. The auth domain must be projectId.firebaseapp.com and appId must be the registered Firebase JavaScript/web app ID. These are public SDK settings, not account credentials. Do not put passwords, bearer/refresh tokens, service accounts, database settings or role/actor fields into Expo extras. No real settings have been enabled by this checkpoint.

The build rejects unknown fields and synthetic catalogue/link modes mixed with native account mode. The runtime also refuses the account screen on web or with a supplied synthetic customer session. Email/password sign-in uses the existing pinned Firebase13.4.0 SDK with inMemoryPersistence, without popup/redirect resolution or AsyncStorage persistence. The provider instance is one-use. Its refresh session is signed out and its named app deleted before private application requests proceed. The password input clears on submit and backgrounding.

The controller uses the resulting ID token only as a bearer credential to GET /v2/customer/account. The gateway must verify signature, verified email, current revocation and active company/actor binding. The client validates the strict customer-account-v1 envelope and company, then the existing MobileCustomerSession independently rechecks the returned actor before activation. Firebase UIDs and token claim roles never become platform actor/company authority. Cookies and actor/company/preview headers are not sent.

The application grant expires at the earlier of provider token expiry or five minutes. Logout, cancel, unmount, backgrounding and expiry clear native account/favourite/pending state. There is no automatic refresh, signup, email/SMS or account-management endpoint in this adapter. Local logout clears this app's credentials; it is not a claim of project-wide token revocation. Native transports that ignore cancellation are bounded by an independent timeout; late replies are discarded. Account response size/chunk count is bounded and redirect/cache/format/ownership failures refuse activation. Screens expose neither password nor token values in controller snapshots.
