## Observed brand facts

- Mobile, web and admin declare **`#5E0202`** as primary. Retain deep burgundy as the recognizable Realtime anchor, subject to operator brand review.
- Mobile declares white `#FFFFFF`, near-white background `#FDFDFF`, body text `#4D4D4D`, secondary text `#717171`, border `#9A8C98` and blue `#0055FF`. Web declares similar neutrals but background `#D3D3D3`. Source constants alone are not an approved accessible token system.
- The actual mark has two rooflines, an acacia/tree silhouette and golden sun. Splash text reads **Realtime Estates LTD** and **LIVE WHERE YOU LOVE**, with a white mark/wordmark on burgundy. The sun supports a restrained gold accent; no precise official gold token was located in this inspection.
- Admin also declares drawer green `#87C441` and a purple button colour. Mobile's home illustration uses purple/grey. These do not justify replacing the company identity with an unrelated green or purple visual theme.
- Mobile font aliases are inconsistent: `Avenir` points to `Metropolis-Regular.otf`; `Poppins` points to `Poppins-Regular.ttf`; `sfPro` also points to `Poppins-Regular.ttf`; `AvenirBold` points to `AvenirNextLTPro-Bold.otf`. Files for Avenir, Poppins, Metropolis and SF Pro are present. No licence file was located in the inspected assets. Choose one properly licensed sans-serif family and explicitly map weights; do not copy these files or trust alias names as font provenance.
- Figma's inspected Home navigation label explicitly uses **Avenir Next, 16 px, 600 (Demi Bold)**, with selected colour **#0055FF**. This verifies one selected element and exposes a source-to-design font mismatch; it does not establish the font, size or blue colour for every component. Preserve the clear sans-serif/navigation intent while using accessible, consistent replacement tokens.

## Recommended UI direction

Use a clean property-search product with burgundy actions, white/light neutral surfaces, a restrained gold brand accent and consistent readable sans-serif typography. Prioritize trustworthy Kenyan property photography, exact KES amounts and useful metadata. A decorative editorial hero or illustrated building grid should not displace real stock/search or substitute for the company's actual brand in the completed product.

Build a shared token/component vocabulary for buttons, fields, validation, status badges, cards, gallery, filters, navigation, tables, timelines, empty/loading/error states and notifications. Web uses a useful responsive results grid and detail/contact layout; mobile uses the same information and contracts with thumb-friendly navigation and bottom actions; admin uses denser work queues with explicit assignment, review and audit history. Shared implementation should not force identical layouts onto all three.

Prepare complete representative screens before expanding: web home/results/detail/enquiry; mobile search/results/detail/saved/enquiry; admin work overview/listings/revision comparison/enquiry detail/viewing detail. Include synthetic-but-labelled content during development; real photos, prices, staff names, contact details and availability require authorized confirmed stock. Compare the proposed screens against the accessible Figma frames and Miro flows once available, recording deliberate changes rather than assuming parity.
