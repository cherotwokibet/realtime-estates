# Opt-in reference moderation API — checkpoint 141

23 October 2026. Independent synthetic candidate; default application and production startup remain unchanged. No migration, disposable preview or vendor system was enabled or changed.

`createApiService` now accepts a separate `referenceModerationMode: 'synthetic-reference-transition-v1'`, requiring the existing synthetic reference draft mode. Invalid or incompatible options refuse construction. Omission leaves the following routes unavailable without querying their SQL:

- `GET /v3/staff/listings/{listingId}/reference-revisions/{revision}/{expectedVersion}` — exact private revision projection.
- `GET /v3/staff/reviews/{listingId}/reference-revisions/{revision}/{expectedVersion}` — current admin pending review.
- `POST /v3/staff/listings/{listingId}/reference-transition-operations/{operationId}` — submit, withdraw, approve or reject using the complete original reviewed facts.
- `GET` on that operation route — original actor-bound receipt recovery, without another transition write.

IDs and version paths are canonical and bounded. Current verified subject and configured company supply context; SQL rechecks current membership, role and listing assignment. Caller company/actor/role headers, cookies, query/fragment overrides, conditional framing, unsupported methods and encoded bodies are refused. The service loads the immutable historical catalogue from restricted SQL and validates the entire review/command/receipt with checkpoint 140 contracts inside the transaction. SQL still compares the submitted facts with the actual stored revision and versions. The catalogue version inside a POST selects only a stored historical catalogue; it grants no authority and cannot override the exact SQL snapshot comparison.

Each successful receipt binds the original operation, action, actor, target, full review, reason, next editorial version and result state. Output validation happens before transaction commit; a malformed returned receipt rolls the transition back. Original GET validates stored command facts and the current actor/path; the SDK must additionally compare that result with the caller's retained original command before settling uncertainty. Exact SQL replay returns the old receipt under current access without a second version increment. Review approval preserves the established availability, media, superseded-review and operational pause rules.

The command wire has a 128 KiB raw/canonical bound, fatal UTF-8 decoding, exact declared length, duplicate-key refusal, integer revision/money tokens and a ten-second streamed-body deadline. The existing deadline-enabled reference reader now also observes request abort and initiates cancellation without waiting on an uncooperative cancel callback. Moderation checks cancellation around reads and before/after transition SQL, so an observed cancellation before return rolls back. This does not claim cancellation after the final transaction check can undo a completed commit; uncertain callers must retain and recover the original operation. The development Node HTTP bridge grants the larger body allowance only to exact canonical transition POST paths; other methods/aliases retain their earlier bounds.
