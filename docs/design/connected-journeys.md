## Permission and information hierarchy

Guest browsing, property enquiry and viewing requests have no unnecessary account gate. Account/favourites/profile designs may be implemented later only with scoped identity/storage; this package does not mark those features complete. An agent sees assigned work and private authorised records, not agency-wide staff management or moderator decisions. Agency admins operate within their company; they cannot select a posted company ID or platform-owner role to expand access. Platform support remains a separately audited operations surface, outside these agency pages. Every API/storage read and write rechecks current membership/ownership; hiding a button is not authorization.

Public property content excludes the private address, prospect/staff notes, owner evidence, job/seal facts and internal review details. Area precision hides exact coordinates; exact precision requires explicit authority and valid coordinates. Only current approved/available/fresh stock appears publicly. Already delivered public bytes cannot be retroactively withdrawn from a viewer; a pause must stop fresh reads and refresh must remove the listing. Exact availability-confirmation timestamps must come from a supported public contract, never from a fabricated local date.

## Recovery and state design

The review inspector provides normal, empty, loading, unavailable and access-ended frames. Loading does not show stale private content. Empty states retain filters and relevant actions. Unavailable states keep unsent work and original request identity in the real application; timeout never proves rollback. Fresh access is required after role/session loss, and old private props are removed. Public not-found does not reveal whether an inaccessible private revision exists.

Write buttons remain disabled while current permission/version/original restoration is unresolved. A cancelled upload stops waiting, retains the original, and does not trigger a replacement request. Unknown attachment operations cannot be abandoned. Leaving a pre-attachment image unattached reads the saved gallery and requires explicit adoption; no attach/delete/resend occurs. Stale text/photo conflicts show local versus saved values. No automatic retry, fresh operation ID or silent merge is a design recovery shortcut.

A viewing request is not a booking. A proposal needs recorded agreement before confirmation. Rescheduling creates a new agreement cycle; old agreement and outcome/cancellation facts stay in history. Captured reminder intent is not delivered email/push/SMS. Provider errors/unavailable/suppressed states remain visible with explicit operator recovery, avoiding repeated messages.

## Responsive and accessibility handoff

Wide agency layouts use a persistent rail and two-column work/detail layout; public results use bounded cards and a clear price/decision hierarchy. At1050px content panels simplify; at760px navigation wraps, columns become a single flow, labels remain above fields and actions wrap rather than overflow. Important costs, errors and unavailable contact actions remain readable at320px. Do not turn comparison tables into unreadably small text; use a labelled scroll region where a table genuinely needs two-dimensional comparison.

Every action has a meaningful text name; touch controls are at least44CSSpx high. Keyboard-visible focus uses a distinct3px outline. Native buttons/forms/selects/details preserve expected keyboard behaviour. Screen navigation moves focus to the new heading; alerts/status use appropriate live roles without presenting success before a saved result. Headings and landmarks remain logical. Fields have labels and required/error help; unknown values differ from blank defaults. Images require descriptive alt text/captions, keyboard expansion and per-file failure feedback; meaningful information never depends on colour alone.

These are design rules and prototype browser checks, not a complete WCAG2.2AA or assistive-technology certification. Actual Android/iOS, two-browser,200% text, touch, screen-reader, slow-network and operator checks remain release work. The prototype state inspector is deliberately not a network-timing or provider-failure test.
