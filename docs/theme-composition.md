# Shared theme composition in web and mobile previews

The existing synthetic brand registry now exposes `getDemoTheme` and `getDemoThemeCss`. Both call the shared palette-only semantic theme generator. A palette is validated without creating a tenant identity, business contact, credential or data-access context. Full `createTenantTheme` validation remains available for actual public company manifests; no real manifest or contact information is fabricated from the demo registry.

Web root composition installs the fixed semantic CSS variables alongside the retained legacy brand variables. The first migrated controls are primary search/actions, selected purpose tabs, brand mark, preview strip/dot, general focus outline and body typography. Primary controls use the shared minimum48px and8px radius. Hover no longer applies a brightness filter to primary action colors, preserving their selected foreground/background pair; shadow and text decoration provide the existing hover affordance. Existing photo overlays and unrelated state colors remain outside this migration.

Mobile composition uses the same numeric/color theme for selected primary text and primary actions, including minimum control size and radius. Other screens and admin controls still need deliberate migration. An Android export is a bundle check, not an installed-device, accessibility or store-distribution result.
