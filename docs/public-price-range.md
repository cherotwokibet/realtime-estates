# Inclusive public base-price ranges

Checkpoint 184, 25 October 2026. This closes a concrete implementation gap in AC-009: public search previously exposed only a maximum price. It does not close the complete public-search task or any release gate. KES 10,000 remains the total recurring service-price baseline per realtor.

The public v2 and gated synthetic v3 search contracts now accept an optional `min` decimal-KES string alongside `max`. Both bounds are inclusive and use the existing safe integer minor-unit conversion. Blank bounds are unrestricted; a supplied bound must be positive, within the existing money ceiling and have at most two decimal places. Exponent, nonnumeric, negative, zero, overprecise, excessive and repeated query values fail closed. A minimum above the maximum is rejected before SQL execution or SDK transport. Equal bounds select that exact cent value.

Either API/SDK price bound retains the existing price-basis requirement: choose sale, or rent with an explicit rental period. Prices describe base price; fees, deposits and unresolved charges remain separately disclosed. Existing company/publication/availability restrictions, saved reference IDs, count/page snapshot semantics, ordering, SQL timeout and response bounds are unchanged. The SQL builder binds the exact decimal-converted integer as text with an explicit bigint cast; caller text does not become SQL syntax. No schema or default feature activation changed.

Final review found that the website's inherited maximum-price validation allowed a blank purpose when a rental period was supplied, while the API/SDK required an explicit purpose. The website now requires rent or buy before accepting either bound in demo, bounded connected and global search modes. Its error identifies the purpose control and retains the entered bounds and period. Invalid global search does not dispatch the search read; the existing independent approved-choice read remains available for correcting reference filters. Bounded catalogue reads retain their prior behavior but never return filtered items for a validation error. The new three-mode regression verifies this correction for minimum, maximum and combined ranges, with omitted and explicitly blank purposes.

The shared SDK snapshots both input strings before I/O, validates the range and sends one anonymous read. The public website keeps the minimum in its parsed filters, form reset key, applied-filter disclosure and allowed pagination URLs. The same inclusive predicates apply in bounded legacy-connected and demo reads. The extracted server-rendered price controls retain exact raw decimal values and associate minimum, maximum or inverted-range errors with the relevant inputs. Reset clears both bounds. These are implementation and component-render checks; browser navigation, hydration and small-screen behavior still require actual current-source verification.
