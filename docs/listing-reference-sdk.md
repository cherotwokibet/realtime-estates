# Synthetic reference draft SDK transport

Checkpoint133, 23 October 2026. The shared API client now supports current/historical catalogue reads, a single combined draft POST and explicit original-receipt GET. It consumes the opt-in API from checkpoint132; platform startup and default migrations still do not enable that feature.

Methods are `getSyntheticReferenceCatalogueV3(version, options)`, `saveSyntheticReferenceDraftV3(command, originalCatalogue, expectedActorId, options)` and `getSyntheticReferenceDraftReceiptV3(command, originalCatalogue, expectedActorId, options)`. The expected actor comes from the caller's verified session and binds the receipt; it is not sent as authority in headers, query or body. The API independently verifies its bearer identity and current company/role/assignment/original requester.

Before dispatch, methods capture strict staff options, detached original catalogue and canonical full command. Invalid facts, stale retained catalogue, extra context, oversized command or pre-aborted signal do not dispatch. One POST carries the original operation ID and expected editorial version; no idempotency header, replacement operation or automatic retry is invented. Response validation binds the entire command, expected actor, one-step revision and every historical attribute against the original catalogue. Later form/catalogue mutations cannot change that captured expectation.

Network/timeout/cancellation after write dispatch and malformed success receipts retain `submissionUncertain`. Recovery is an explicit GET with no write body. A403/404 or failed recovery read does not settle a previously uncertain write: callers must retain that original attempt. A valid original receipt can be recovered after later catalogue activation, while new writes using a stale catalogue conflict. Explicit identical replay is available by calling the same save method with the same original facts; the SDK never does so automatically.

The reference transport bounds catalogue replies at6MiB and draft receipts at1MiB. It checks content encoding, exact canonical declared length, actual streamed bytes, fatal UTF-8, decoded duplicate keys, integer revision/money tokens and fixed route/version identity. Empty frames are bounded/yielded; hostile or late bodies are cancelled without awaiting an uncooperative cancellation promise. Existing timeout and abort races remain active while reading the body. Catalogue reads above1MiB are supported deliberately, rather than raising the receipt bound for all methods.
