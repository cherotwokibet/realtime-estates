| Route                                                                        | Behavior                                                                                              |
| ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `GET /v3/staff/reference-catalogues/current`                                 | Current owner-installed synthetic catalogue.                                                          |
| `GET /v3/staff/reference-catalogues/:version`                                | Retained explicit catalogue version, with current staff access.                                       |
| `POST /v3/staff/listings/:listingId/reference-draft-operations/:operationId` | Strict combined draft command; one SQL save with the shared canonical command and receipt validators. |
| `GET /v3/staff/listings/:listingId/reference-draft-operations/:operationId`  | Authorized saved original; no replay write and no new request identity.                               |

Tenant comes from trusted service configuration and actor from verified authorization. Current agent/admin membership is checked in the transaction. SQL save/original reads additionally check current company, assignment and original requester. A catalogue is global synthetic reference data, exposed only through a staff-checked SQL function; runtime retains no direct manifest table SELECT or catalogue/pointer write grant.

POST loads the server's retained catalogue for the explicit selected version, never caller-provided labels or reference authority. SQL takes a shared lock on the current pointer through the save transaction, while owner activation takes an update lock, and checks catalogue currency. An identical existing operation can replay after a newer catalogue is activated. GET's SQL context projects the original request independently from its saved receipt and includes the original immutable catalogue internally. The API binds path, verified actor, original command and all receipt attributes before committing/responding. It returns only the checked receipt, not that internal recovery context. Real two-connection lock behavior remains an unrun hosted PostgreSQL check.

Requests reject query/fragment context, cookies, authority headers, conditional/range aliases, content encodings, duplicate decoded JSON fields, decimal/exponent revision or money tokens, inconsistent body length and unsupported fields. POST accepts at most128KiB of UTF-8 JSON, with a10second body deadline and bounded empty-frame handling. Deadline/oversize cancellation is not awaited when a stream refuses to finish cancelling. These stricter stream limits and string version token mode apply to the new reference body path; existing routes retain their prior defaults.

Catalogues have their own6MiB validated output bound. A legitimate1800-node catalogue containing160-scalar Unicode labels exceeded1MiB and was successfully checked and served in the test. Future SDK catalogue reads must use this separate bound rather than a1MiB receipt transport. All API replies use existing private `no-store` handling.
