# Controlled Firebase provider rehearsal

The maintained manual runner is scripts/firebase-auth-provider-rehearsal.mjs. Checkpoint461 completed one real provider lifecycle on19 November2026; see [sanitized evidence](evidence/2026-11-19-auth461-summary.md). It is not an automated probe and must not create accounts on every CI run or heartbeat. CI runs only the injected safeguard test file.

Before an explicitly needed repeat, use native Firebase get_project/get_environment to verify boniface-realtor-staging is ACTIVE and billing is disabled; get the registered web application's public SDK configuration. The script accepts one JSON object on stdin and the exact --owned-staging-auth-rehearsal flag. Input fields are policy=owned-staging-auth-public-rest-v1, billingEnabled=false, billingCheckedAt=current ISO time from the actual readback and sdkConfig=that native public result. Readback older than ten minutes, a different project/app/domain, emulator/TLS bypass or a live GitHub Actions invocation refuses before account creation. Do not supply an arbitrary pre-existing account or persisted password/token.

The runner creates at most one random example.invalid account, verifies Google signatures using public keys, signs in, refreshes and checks lookup ownership before self-deleting. It confirms absence and refresh refusal. Password/ID/refresh tokens are generated/handled in process memory; stdout is a sanitized report. A network-ambiguous signup may recover only that same account once for cleanup, never a second signup. Explicit quota/security/provider refusal stops rather than changing projects, disabling controls or buying capacity. Preserve a failed report. If cleanupRequired is true, its syntheticEmailForManualCleanup identifies only the new test account; review it in the owned project's Authentication console, delete only that exact account and record the readback. Never delete other accounts to clear a failed test.

A successful report must have transport=live-provider, status=passed, livePublicProviderLifecycleVerified=true, all eight checks true and cleanupCompleted=true/cleanupRequired=false. Mock tests explicitly set injected-test-only and cannot produce a live pass. No verification/reset email or SMS is sent. No Admin SDK user-management credentials are assumed.
