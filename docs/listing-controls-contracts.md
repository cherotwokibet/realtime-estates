# Availability and publication command contracts — 16 October 2026

Shared domain contracts now define two exact intents: `confirm_availability` with one availability value, and `set_publication` with paused/published/archived. Each has an operation UUID, listing UUID and canonical positive expected listing version. No tenant, actor, role, arbitrary timestamp, publication side effect or caller-selected SQL function is accepted. Commands and kind-correlated original receipts are detached and frozen. Stored receipts bind route kind, target, operation, verified actor, exact original request and next listing version; extra fields, accessors, hidden keys, malformed clocks and incompatible terminal decisions fail closed. Receipts are historical results, never current listing projections.

The pure planner consumes independently authorized current listing facts, verified staff role and a trusted operation clock. It grants no tenant/assignment access. Rules retained from the existing SQL:

| Intent | Policy |
| --- | --- |
| Confirm availability | Assigned agent or admin. Refresh confirmation and increment listing version. Non-available stock auto-pauses a published listing. Available confirmation does not automatically republish paused/unpublished/archived stock. Archived state/time and selected approved snapshot remain intact. |
| Pause | Assigned agent or admin; agent cannot reopen archived stock. Admin may move archived stock to paused. |
| Publish | Admin only; selected revision must match the approved snapshot, stock must be available and confirmation must be strictly newer than30 days. Reopening archived stock is explicit and clears its archived timestamp. Publication never refreshes availability confirmation. |
| Archive | Admin only; set archive time, retain selected approved snapshot and availability facts. |

New guarded clock rule: future-dated availability confirmation refuses a fresh confirmation or publish command. Pause/archive remain possible to hide stock safely. Comparisons preserve microseconds, including one microsecond beyond the exact30-day boundary. This rule is in the new planner only; existing SQL has not yet been updated to implement these guarded contracts.

Unauthorized new work throws before durable reservation. For authorized fresh commands, stale version conflicts before business refusal; safe integer exhaustion refuses before clock/publication checks. Explicit repeat confirmations and repeated publication intent increment once per new operation, matching existing versioned-write semantics. Applied receipt result contains only the exact next listing version; it makes no claim about current public visibility. Publication state, availability, freshness and catalogue eligibility must be read independently after success.
