# Reachable staff enquiry queue and server follow-up filters

Checkpoint 188, 25 October 2026. The v2 staff queue exposes a bounded newest slice with a `truncated` flag, so older leads cannot be reached through that queue and a loaded-slice reminder cannot find older due work. The separate authenticated v3 read adds keyset paging and server follow-up filters. The original v2 queue, assignee directory, detail and write contracts remain available. KES 10,000 remains the total recurring service-price baseline per realtor; no provider notification, purchase or schema change is introduced.

`GET /v3/staff/enquiries` accepts only optional `limit` (canonical 1–100, default 50), `filter` (`all`, `open`, `overdue` or `today`, default `all`) and `after` (a canonical lowercase UUID). Unknown, repeated, blank, padded and malformed query values fail closed, including identical repeated values. The query is bounded to 8192 encoded bytes. There is no offset, caller-selected tenant, actor, assignment, clock, date interval or sort. This exact v3 staff route uses the ordinary verified identity and current staff membership; it is isolated from the synthetic reference feature gate and does not enable other v3 routes.

Each response has exactly `policy: 'staff-enquiry-queue-v3'`, `items` (the existing safe v2 summary DTOs), `limit`, `filter`, `after` (UUID or null), `hasMore`, `nextAfter` (UUID or null), `asOf` (canonical UTC milliseconds) and `timeZone: 'Africa/Nairobi'`. It contains no total or company-wide reminder count. One extra matching row establishes `hasMore`; only then is `nextAfter` the last returned item's ID. An empty or final page returns null. Summary rows contain no phone, email, private message, private contact history or authority fields.

The data read is one SQL statement over the existing forced-RLS enquiry table, after the ordinary staff check and a local two-second statement timeout. Its materialized clock, visible anchor and filtered page share that statement snapshot. Both the anchor and candidate rows retain the trusted tenant restriction and runtime assignment visibility. A supplied anchor must still be visible to the current caller; missing, foreign, deleted and reassigned-away anchors all return the same 404 response. They never restart or widen the read. The anchor need not still satisfy the selected filter, so closing a visible lead between pages does not invalidate its position.

Ordering is fixed at database `created_at DESC, id ASC`. The cursor UUID retrieves its exact stored creation timestamp: the comparison is an earlier timestamp, or the same timestamp with a greater ID. No timestamp is reconstructed from the millisecond DTO, and no caller timestamp is accepted. This avoids skipped rows when distinct database microseconds render as the same millisecond. UUID ordering breaks exact database timestamp ties only. SDK validation can check nonincreasing projected creation milliseconds but cannot infer the hidden database tie order from that lossy projection.

The captured SQL clock is truncated to milliseconds once per page. `open` includes new, assigned, contacted and qualified enquiries. `overdue` includes only open enquiries with a nonnull next action strictly before `asOf`. `today` includes only open enquiries due at or after `asOf` and strictly before the next Nairobi civil midnight. Exactly-now work belongs to today; overdue work does not also appear in today. Closed-won, closed-lost and spam historical follow-up dates are excluded from both reminder filters. All filters preserve the same creation ordering and current authorized visibility. Each page has its own server clock and data snapshot: changes between reads can change membership or visibility, so refresh/filter changes must explicitly restart from the first page. This is a paged current queue, not a frozen multi-request export or notification scheduler.

The SDK exports `StaffEnquiryQueueFilterV3`, `StaffEnquiryQueueInputV3`, `StaffEnquiryQueuePageV3`, `validateStaffEnquiryQueueInputV3(input)` and `validateStaffEnquiryQueuePageV3(value, input?)`. The input validator returns a frozen normalized `{ limit, filter, after }`; its null `after` must be omitted when constructing a new input. `listStaffEnquiriesV3(input, options)` keeps the query separate from required staff options, snapshots both, rejects unknown fields/accessors before I/O, and performs one authenticated anonymous-cookie-free GET. It validates exact page metadata, safe summaries, cursor/cardinality consistency, filter membership against the captured server clock and duplicate identities. The response stream is capped at one MiB, with UTF-8, framing, duplicate-key/integer-token, empty-frame and cancellation guards. Missing cursor and other errors do not trigger an automatic retry or broader read.

The opt-in development enquiry preview allows only the exact v3 queue route and uses the same query parser as the API. Its current host, origin, cookie, method, token and company selection controls remain intact. Default staff preview does not expose the queue.

Its bounded exact query parser accepts only the three queue fields; existing list/directory/detail/write routes keep their old query rules. Fixed server-only identities, instance binding, private/no-store responses and browser credential/context rejection remain. The browser client captures detached input before one bounded read and validates the returned page against that exact input. There is no fallback to the old newest slice.

The workspace offers all/open/overdue/still-due-today server queues, older/previous/first pages, and local assigned/unassigned filters explicitly scoped to the current page. Refresh and changing the server filter restart at the first page. Page changes retain the open detail and its raw input/original command; selecting another enquiry still requires the existing explicit discard/recovery controls. Superseded reads are aborted; generation guards prevent an earlier success repopulating data after denial. Current denial clears private queue/detail/directory and page history. Loaded-page reminder counts keep their separately disclosed browser clock; server filtering displays its own captured time. Neither is a global count or a scheduler.
