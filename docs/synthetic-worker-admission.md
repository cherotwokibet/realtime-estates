## Frozen boundary

`@realtor/media/worker-admission` owns one stable configured local worker root, separate from the journal store and native attempt parent. Creation generates a worker identity and canonical marker binding it to one journal identity. Reopening requires those same expected identities. Changing roots/identities to evade blocked history violates the contract. Use one root for the host worker scope; an independent new root does not establish global admission for the old scope.

`reserve({jobId,claimId})` exclusively creates the fixed active directory and commits bounded canonical owner bytes before returning a fresh opaque runtime permit. It must precede capture/claim/native work in the future orchestrator. An existing active directory always blocks, including an empty partial, a valid old owner, an armed attempt or a recorded termination. Reopening never reconstructs the permit. Reserve grants a shared worker slot only; the journal's permanent job reservation enforces attempt freshness.

Before native launch, `arm(permit,reservation)` synchronously marks the permit armed and consumes the journal's same-instance one-use launch ticket. `consumeLaunchTicket` never accepts a copied, foreign, already consumed, observed or reopened ticket; it returns the immutable intent only. The worker checks its exact job/claim/journal binding, then commits and reads back launch bytes before arm returns. Historical journal inspection is a consistency read, never launch authority. Failure from arming onward retains the worker slot, even if no decoder was ultimately started. A trusted caller launches only after successful arm.

`releaseBeforeLaunch` accepts only the same live unarmed permit. It records `not_launched`, never a fabricated OS termination. This handles input/auth/claim failures without blocking unrelated future work. It does not repair or release permanent journal/job/native reservations.

`confirmTermination` requires the same armed live permit and the trusted caller's actual native supervisor outcome. It records through the live journal ticket and compares exact terminal readback. Unknown containment is recorded and permanently retained. Only confirmed `job_empty` with zero active processes can enter release; failed/cancelled/timed-out but empty native outcomes may release the shared slot while providing no output-success authority. Actual successful exit and separate byte verification are still required before output installation/sealing. Simulated unit observations do not prove OS termination.

## Release and startup rules

Release first commits and reads canonical completion bytes, exclusively reserves `history/<reservationId>` and atomically renames the owned active directory into its absent `slot` child. Completed owner/launch/termination records remain retained; no files are deleted or overwritten. An existing history envelope refuses release. A failed rename retains the active slot/envelope; uncertain rename never triggers a retry, rollback or mutation of the active path, which may already belong to a successor. Post-rename verification examines the archive only.

Only the live permit can release; journal history, PID disappearance, clock/SQL lease expiry, factory reopening and a known historical terminal cannot release an active slot. `inspect()` gives bounded explicit idle/blocked status and owner facts when valid, without a startup scan, reconstructed permit or automatic work. Close stops admission and drains admitted I/O; it neither releases active work nor closes the caller-owned journal. A closed controller cannot be reused. Persisted incomplete/unknown active work requires a separately reviewed recovery procedure, which remains unimplemented.

Strict own-data shapes, canonical records at most4096 UTF8 bytes, exclusive writes, bounded reads, sync/readback, stable current ancestry and file/directory identity checks reject malformed or changed paths. These checks require a trusted local filesystem and writer configuration. They establish neither hostile same-user race resistance, Windows ACL/network/native resource isolation, power-loss/directory-entry durability nor production object backup. Rename does not expose an operating-system no-replace primitive; the exclusive envelope and trusted-writer contract bound this implementation.
