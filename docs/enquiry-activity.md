# Enquiry activity database contract - 13 October 2026

Additive migration0011 provides app_api.list_enquiry_activity(enquiry UUID,limit1..100). Current active admin or currently assigned active agent can read a company-scoped enquiry; unknown/foreign/unassigned resources return the same unavailable outcome. Revocation/reassignment is checked on every read. The function is SECURITY DEFINER with fixed pg_catalog search_path and PUBLIC execution revoked; api_runtime receives only function execution. No receipt-table DML/read privilege is added.

Minimal events include capture and applied v2 assign/transition/reschedule changes. No-op/rejected/conflicted operations are excluded. Each event returns eventId,kind,actorId,occurredAt,version,status,assignedAgentId,nextActionAt. Initial capture has requester ID or null; that ID must not be assumed to be a staff identity for guest-authenticated capture. Event identifiers require kind/version context for UI keys. No private request body, command hash, closure reason, contact phone/email/message, secret or invented staff name is projected. This intentionally differs from requester-private exact receipt recovery: authorized current team members can see minimal applied activity, not another requester's original command.

Newest saved version first, stable ID tiebreak; at most limit+1 rows considered for truthful truncated flag. Response includes limit,truncated,currentVersion and coverage='capture-and-v2-operations'. It is not a complete audit trail: legacy writes are not invented, current version may exceed the newest available activity and truncated=false means only end of this supported slice. Capture status starts new; applied workflow status/follow-up facts are historical values. Recording contacted does not prove a call/message was sent by the system. No viewing event is invented.
