# Staging Cloud SQL IAM connections

This is implemented local connection composition, not a deployment receipt. Billing is disabled. Obtain a reviewed selected-region quote and resolve the existing paid-plan restriction before provisioning billable services.

Use NODE_ENV=production, APP_ENV=staging and the attached Cloud Run identity. GOOGLE_CLOUD_PROJECT must match the Firebase/API project; K_SERVICE must be present. The server-only BROWSER_IDENTITY_CLOUD_SQL_CONFIG (web/admin) or HOSTED_API_CLOUD_SQL_CONFIG (API) accepts exactly:

    {"instanceConnectionName":"boniface-realtor-staging:africa-south1:synthetic-test","database":"realtor","serviceAccount":"realtor-web@boniface-realtor-staging.iam.gserviceaccount.com","ipType":"PRIVATE"}

Names are illustrative only; no instance, service account or region has been provisioned/selected by this example. Configure a separate dedicated service account for web, admin and API. Remove the corresponding _DATABASE_URL when using IAM mode. Extra keys, a different project, credential-file overrides and PG environment defaults refuse. Service account database usernames remove .gserviceaccount.com (example: realtor-web@boniface-realtor-staging.iam), with a maximum 63 characters. The configured identity must match the real SQL session user. The connector uses attached workload credentials; no service account key or database password belongs in configuration.

The explicit alternative _DATABASE_URL requires a username, password and sslmode=verify-full, with no other query parameters. Never configure both transports. Connector failure returns an unavailable error and cannot switch to the URL alternative. PUBLIC and PRIVATE are explicit choices, not network auto-discovery. Private IP requires suitable Cloud Run VPC routing; the connector alone does not create that route. Public connectivity still requires reviewed networking/egress policy.

Before a real deployment, the controlled project needs Cloud SQL Admin API, Cloud SQL IAM database authentication enabled, each service account added as an IAM database user, and the documented Cloud SQL Client and Cloud SQL Instance User permissions. These are prerequisites, not actions performed here. IAM access does not grant SQL table privileges. A migration owner must review/apply migrations separately, set dedicated login role attributes, and apply only the runtime's direct privileges. API login needs the reviewed NOINHERIT api_runtime membership and lookup function; browser identities must have no application role memberships.

Browser SQL access: USAGE on identity; SELECT only on firebase_actor_bindings; SELECT/INSERT/UPDATE/DELETE only on browser_state and that app's customer_browser_originals or staff_browser_originals table. Auth-only profile needs no originals. Other identity tables, binding writes, schema/table ownership, application schema access and administrative/replication authority refuse. Browser logins must be NOINHERIT, non-superuser and NOBYPASSRLS, without CREATEDB/CREATEROLE/REPLICATION or other memberships. Do not grant owner permissions to bypass a failed attestation. Provider-managed IAM roles may introduce attributes/memberships that require an explicit reviewed compatibility decision; this has not been tested against Cloud SQL.

Each API process limits its pool to five connections; each web/admin identity runtime shares one three-connection pool for authentication and originals. Pool initialization is lazy and shared by concurrent callers. Query/connection deadlines and idle cleanup are bounded. Pool closure closes the connector and destroys any connection acquired after closure. Startup validates API database role safety; browser queries validate their role before each payload query. These counts are per instance, not project-wide limits; Cloud Run max instances and SQL connection capacity still need a reviewed deployment budget.

Pinned connector 1.13.0 provides automatic IAM token/certificate handling with its stream. It exposes no refreshStrategy option; do not copy a Java/Python LAZY setting into this Node configuration. Live token refresh during idle periods, workload ADC, managed role behavior, TCP concurrency, VPC paths, ingress and shutdown require acceptance evidence. Current tests inject the connector transport and use disposable PGlite SQL; the ten HTTP profiles are local origin/configuration checks only.

BROWSER_IDENTITY_STORAGE_KEY remains an independent 32-byte encryption secret even in IAM mode. Managed storage, secret rotation, retained originals cleanup, account erasure and migration rollback need review. No real keys, cookies or customer records are committed.
