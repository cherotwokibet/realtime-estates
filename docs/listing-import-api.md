# Authenticated listing import preview API

17 October 2026, checkpoint113. Fixed POST `/v2/staff/listing-import-preview` accepts an exact JSON object containing only `csv`. The bounded256KiB JSON envelope allows escaping expansion; the shared contract still enforces decoded32KiB UTF-8 CSV and100 records. Duplicate JSON keys, wrong types, unknown fields, caller authority headers, cookies, encoding/transfer ambiguity, conditional/range headers, query/fragment context and idempotency keys are rejected. Declared length must match the actual body. Responses use the maintained private no-store policy.

Identity comes from the configured verifier and company from server configuration. In a trusted transaction the service checks current admin membership, parses the shared CSV preview, deduplicates syntactically valid candidate slugs (even for rows with other errors), and calls the fixed read-only import-stock projection. An empty candidate set needs no stock query, but still requires current admin access. Database responses must be bounded dense own-data arrays containing only unique requested slugs; malformed or unrequested projections fail before transaction commit. Accessors are not invoked. The service then recomputes the preview with checked existing-stock facts. No caller-supplied collision facts are trusted.

This creates no listings, operations, reservations or publications. Preview facts may change before creation; the actual creation transaction must recheck authority and uniqueness. Existing row errors remain explicit and valid neighbors retain normalized draft content and exact KES minor units.
