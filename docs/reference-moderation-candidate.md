# Isolated reference-aware moderation candidate

Checkpoint139 — 23 October2026.

The new listing-reference-moderation.sql proposal provides a complete SQL candidate for adopted-reference submission, withdrawal, pending review, approval/rejection, original receipt recovery and approved public reference facts. It is not a default migration, API route, SDK method, reviewer UI or enabled preview feature. The existing default and preview still load only the earlier reference proposals, so adopted submission remains blocked there.

Private projections bind the exact editorial version and listing version to the saved full content, original reference snapshot, operational publication/availability facts and ordered media fingerprints. They verify content and attributes against the immutable original draft receipt. Catalogue activation cannot silently replace the reviewed labels. Pending review reads require current admin access; revision reads and transitions repeat current staff/company/assignment checks.

Each transition requires an operation UUID and the complete exact projection. Altered content, attributes, gallery, listing currency or extra fields are refused. An append-only, tenant-scoped receipt is inserted inside the same transaction before invoking the existing submission, withdrawal or decision function. The reference trigger accepts only the matching actor/revision/version/state transition backed by that private receipt. Runtime SQL has no table-write permission, and a caller-controlled custom setting cannot create a permit. Legacy review commands cannot reuse a permit from another version. Original replay/recovery binds the original actor, exact request and current authorization; replay returns its receipt without another state change.

The candidate deliberately delegates media sealing, complete draft validation, availability freshness, superseded-review checks, self-approval audit and operational pause/archive preservation to the established commands. It does not replace those checks. A failed underlying command rolls back its proposed receipt. Approval additionally records immutable reference attributes in a private sidecar keyed to the approved revision/version, in the same transaction as the existing public snapshot and publication pointer. A late sidecar failure rolls all of these changes back.

The public candidate view inherits the existing tenant, enabled-account, publication, availability and freshness filters. It exposes approved reference attributes only from the immutable sidecar matching the approved revision. Unadopted legacy stock remains visible with explicit null reference fields. Private address and area-level coordinates do not enter the public projection. The view never substitutes the latest catalogue for approved labels.
