## Operator behavior

Settings and report review now offer an explicit **Close this original safely** action. It asks the server to inspect the exact original under current admin authority. If already applied, the server returns its complete matched receipt. Otherwise it permanently retires that operation ID in an immutable, tenant/kind/actor/full-request-bound ledger. Future writes with the retired ID are refused, including a changed payload with the same ID. This is a new explicit operation, not an inference from HTTP404/409/400 and not an undo of saved publication/review.

Only a complete current-scope resolution receipt can release the unchanged encrypted browser slot. Preparation/readback still precedes dispatch, and release still requires a current-authorized reopen of the original. Another actor/company/request/outcome, malformed receipt, failed persistence, access denial, timeout or obsolete completion cannot clear it. A lost resolution reply leaves the encrypted original available for authorized same-preview reload and an idempotent repeat of this exact close. Settings require refreshed current saved content or explicit comparison/adoption before a new operation. Reports clear the resolved selection and require loading the current queue.

## Maintained implementation

Migration0038 adds a FORCE-RLS, no-direct-runtime-grant, append-only cancellation ledger with full original validation. Settings/report writer entrypoints take the same tenant/member lock as resolution before checking cancellation and invoking the preserved command implementation. The earlier implementations are renamed and their PUBLIC/API/media execution grants revoked; the only runtime writers are the guarded entrypoints. Report resolution also coordinates with its existing operation advisory lock. Existing applied receipts, publication, report decisions, versions and old audit events are unchanged by a retirement. The ledger itself records immutable attribution/facts; separate audit-feed presentation is not implemented.

A strict shared domain resolution contract, fixed authenticated SDK/API path, developer BFF action and both screen adapters implement the protocol. The API defaults OFF unless privateOperationResolutionMode is explicitly synthetic-serialized-original-v1, and production refuses that option. The BFF remains default-off/development-only with its configured recovery key and double fresh current-admin checks. Disposable staff/audit preview builders explicitly enable the synthetic mode; a real launcher test verifies the preview host guard forwards the new route. No production API/provider or managed database was provisioned or enabled.

The design uses PostgreSQL17's documented application-controlled locking and owner-controlled function renaming: [explicit locking](https://www.postgresql.org/docs/17/explicit-locking.html), [ALTER FUNCTION](https://www.postgresql.org/docs/17/sql-alterfunction.html). Draining old writers is our rollout constraint; those references are not evidence that an active rolling migration was tested.

## Migration and recovery limits

Before any future non-disposable deployment of0038, stop/drain replacement API writers and replace their connection pools/prepared plans, apply the migration, verify the guarded functions/grants, then admit traffic. Cold disposable migrations are tested; this change does not establish a rolling-upgrade guarantee for already executing old function bodies. The synthetic API mode cannot be enabled in production. Production enablement requires its own reviewed rollout and current-authority integration.

Retirement markers must remain with command receipts during backup/restore/rollback. A restored older database must reconcile/reapply post-snapshot cancellations before writes are enabled. That restore/delta procedure has not been executed here. Terminality checks concern the current authoritative history, not an untested database rewind. Immutable original retention also needs the eventual operational retention/export policy.

Recovery still requires the same preview key, instance, tenant, actor and tab storage. Key custody, backup, rotation and instance/data-epoch migration remain open. Closing a tab or restarting a disposable preview can make its capsule unavailable; no restart/production durability claim is made. The new protocol is only for current-admin settings/report commands, not agent capture, privacy reviewer or invitation-recipient authority.
