# Shared client evidence — 10 October 2026

The new packages/api-client workspace implements the existing database-mode public catalogue and enquiry routes. It has no runtime dependencies. This is a transport boundary for future web/mobile integration, not a connected UI or a complete property/fee contract.

Agent runs completed with 20 passing checks: 14 controlled transport/validation checks, 5 actual Node Fetch checks using ephemeral loopback HTTP servers, and 1 integration against the actual API service, actual migration and restricted PGlite runtime login. Root then integrated the workspace/lock/test scripts and ran `npm test` successfully: 31 domain + 5 demo + 32 API + 19 client transport/HTTP + 1 client/service integration + 18 SQL = 106 checks, zero failures. All seven workspace typechecks passed. Logs: checkpoint-tests.txt and checkpoint-types.txt. The existing final web/admin builds and mobile JS export remain valid; their application inputs were unchanged by this package integration.

The actual HTTP cases reject cross-origin 302/303/307/308 POST redirects before the destination receives any request, enquiry body or bearer token. A deliberately accepted POST with no receipt times out as uncertain; manual retry retains its original key/body and receives one stable controlled-server receipt. The SQL-backed integration separately verifies durable enquiry replay/conflict, exact minor-unit money, separate-company public projections, hidden address/area coordinates and rejection of a stale notice version.

Request credentials are explicit per call; there is no shared token state or automatic retry. Responses use strict allowlists, safe typed errors and immutable DTOs. Unknown fees are not fabricated as zero. The response-size check occurs after reading text and is not a streaming memory bound.

Not verified here: browser CORS/transport, React Native redirect/cookie behavior, real JWT provider sessions, deployed HTTP/PostgreSQL/PostGIS, physical devices or media processing. Before native sends real tokens or contact data, prove the exact transport enforces redirect refusal and omits ambient credentials. The official [React Native networking documentation](https://reactnative.dev/docs/next/network) identifies Fetch implementation limitations; passing Node tests cannot establish native equivalence. Existing demo endpoints and fixture IDs are intentionally separate from the persistent API contract.
