# Bounded admin audit read candidate — 3 November 2026

Owner: Boniface + Codex. Supporting implementation for 08-7, which remains open.

Added `database/proposals/admin-audit-reads.sql`, explicitly excluded from the normal migration runner. It exposes a fixed metadata projection of the existing append-only audit table to the current active administrator of the enabled current company. Each invocation rechecks authority. Pages contain at most twenty rows, descending identity IDs, with optional exact actor/object UUID filters and an exclusive `nextBefore` cursor. A company/descending-ID index supports traversal. Event and object versions are JSON strings, preserving bigint values above JavaScript's safe integer range.

Summary JSON, private contact information, reasons and arbitrary correlation text are excluded. A later reason/correlation projection needs an explicit safe contract; copying raw summaries is unsafe. The existing underlying administrator raw-table SELECT grant is unchanged; this candidate does not claim to remove that broader existing access. No new write or impersonation endpoint is provided.

Verification: `node --test --test-concurrency=1 database/tests/admin-audit-candidate.test.mjs` passed 3/3 with zero failures or skips. Raw final output: `docs/evidence/audit317-database.txt`. Disposable PGlite applies the maintained migration order and this candidate; calls execute under restricted `api_runtime` with company/actor transaction context. Assertions cover foreign-company exclusion, exact UUID filters, cursor progression with a newer inserted event, invalid bounds, current agent/customer/foreign/missing actor denial, demotion/revocation/disabled-company denial, and runtime DELETE denial plus owner UPDATE/DELETE append-only triggers. Seeded event includes synthetic private summary/correlation sentinels; neither appears in the response. Exact `9007199254740993` version is preserved.

Limits: seeded audit facts exercise the read boundary, not every real admin command's event creation. This is a live descending keyset, not an immutable cross-request snapshot: concurrent transactions can commit identity IDs out of order; a complete exported snapshot needs a separately designed consistent boundary. Query count is bounded, but actor/object filtering may scan company history; no production load benchmark is claimed. No HTTP route, signed JWT composition, strict SDK decoder, admin BFF/UI, browser/device/hosted race or deployment activation has been implemented for this candidate. No app GitHub push, Actions run, spending, vendor-resource or live-system change.
