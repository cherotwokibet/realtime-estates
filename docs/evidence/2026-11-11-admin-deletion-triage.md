# Synthetic admin deletion triage browser checkpoint

11 November 2026 EAT, checkpoint 398. The opted-in admin workspace links to Account deletion requests. The screen loads the signed company queue, requires an explicit disposition choice and confirmation, and lets the reviewer check the original receipt after an uncertain reply. A missing original permits an explicit retry of the same operation. This preview holds the pending command in memory for the open page. The BFF uses a server-owned synthetic reviewer token and verifies the exact request and operation. The browser receives scoped queue and receipt data through the same-origin BFF.

An actual local browser opened the page from the workspace link and loaded two synthetic requests. The confirmation button was disabled until a disposition was selected. A committed write returned a simulated 503. Check original decision issued a GET for the same customer, request and operation and recovered the saved disposition with 200. Reloading the queue showed only the second request. After the fixture revoked reviewer membership, the queue returned 403, the row disappeared and the load button was disabled. See the three deletion398 admin screenshots. Reloading the browser during an uncertain write was outside this rehearsal.

Two boundary tests passed, covering default-off, injected authority, origin, duplicate filters, route binding and rejection of a receipt with a different reviewer. Admin typecheck, formatting and the local production build passed. The initial typecheck exposed a Headers iterator unsupported by the admin TypeScript configuration and was fixed with Headers.forEach. The first browser fixture shutdown hit a Windows taskkill exit race. A subsequent piped run exposed early stdin consumption and the owned process tree was retired. The launcher now waits for its child to exit and handles piped quit after setup. A final piped quit passed and port 3139 was clear. Evidence is in deletion398-boundary.txt and deletion398-admin-build.txt.
