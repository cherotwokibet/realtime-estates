# Reference moderation domain contracts — checkpoint 140

23 October 2026. Independently authored synthetic implementation; not a default migration, enabled API, reviewer screen or launch approval.

`packages/domain/src/listing-reference-moderation.ts` now validates the candidate SQL's complete private revision projection, all four transition commands, exact original transition receipts and a separate two-field public reference extension. The private projection includes availability confirmation time, operational publication context, both version strings, full canonical content, historical reference labels and ordered photo fingerprints. The caller supplies the expected listing/revision/editorial version and a server-controlled original catalogue. A newer catalogue cannot silently rename reviewed facts.

Commands require the appropriate draft/pending source state, a canonical operation UUID, versions with room for the next write, an explicit null reason except for a bounded canonical rejection reason, and the entire reviewed projection. A receipt must match the retained original command, verified original actor, exact next editorial version and correct result state. These functions detach and freeze their results; ordinary getters, symbols, hidden properties, malformed arrays, extra fields and private/public shape substitution fail closed. They do not grant authorization, prove sealed image bytes, evaluate current availability freshness or establish publication eligibility. Those remain transactional SQL/application responsibilities.

The public extension accepts only `{attributes, revisionVersion}`: either both null for unadopted legacy stock, or a historical canonical attribute snapshot and approved version string. It rejects private review/content/actor fields. It is deliberately not a validator for a complete public listing: the existing public listing contract and SQL tenant/publication/availability/freshness gating must still apply. API field mapping and public API integration remain open.

Canonical detached review, command and receipt JSON is bounded to 131,072 UTF-8 bytes. Future transport must cap raw bytes before JSON parsing, reject duplicate/noncanonical integer tokens, and enforce its own timeout/encoding rules. The domain size check is not a substitute for those transport limits. Draft projections may have no photos or unaccepted/unsealed photos: read access does not assert submit readiness.
