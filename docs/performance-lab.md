# Local performance and inventory budgets

29 October2026. These targets are recorded before the first measurement. No measured value is a production SLA. Boniface's KES10,000 total monthly client price does not buy an unbounded inventory or usage promise.

The reproducible lab is a planning scenario: two synthetic companies,500 approved properties each, four photo-metadata records per property, mixed monthly/daily rental and sale prices, studio/one-to-eight bedroom properties and nullable shared bathrooms. Each property passes the existing disposable guarded draft, submission and approval routines. This is larger than the32-row functional journey fixture. It represents an illustrative initial two-company catalogue, not a measured customer distribution. Real decoded image transfer/processing, enquiries, writes, push, provider latency and network/device contention require separate measurements.

[Machine-readable targets](../scripts/performance-budget.json): four closed-loop clients,12 rounds each, at most48 timed API reads plus bounded warmups/correctness probes. Measure first cold request separately; warm p95≤1000ms, p99≤2000ms, max/deadline≤5000ms, response≤2MiB, zero unexpected statuses or incorrect totals/tenant leaks. Include default/price/bedroom/normalized-location/amenity search, later pages, full100-row bound and empty results. Do not infer sustainable requests/second from a short burst. The240/minute limiter stays enabled. Record every failed assertion/timeout; do not automatically rerun to replace failed results.

Measure the current Next production **demo** site separately on owned loopback: cold response and five warm requests per public route, p95 headers≤1000ms, HTML≤512KiB and unique initially referenced local JavaScript≤500KiB gzip per route. Browser caching and CDN are absent. A production demo server does not establish connected database rendering, interaction latency, Core Web Vitals or production readiness. Keep the existing refusal of a production loopback synthetic API; do not relax it for a green benchmark.

Record source commit plus dirty-file hashes, runtime/OS/CPU/memory, seeded counts, exact request mix, warmup exclusion, nearest-rank percentiles, response bytes, errors, cold/warm separation and deterministic assertions. PGlite is single-process WASM PostgreSQL; multi-session/hosted lock/plan behavior is not verified by this fixture. Low available host memory may affect the result. Use one owned process at a time and close it after measurement.

Field work remains explicitly unmeasured: real mobile p75 LCP/INP/CLS, slow-network galleries/uploads, real PostgreSQL load, production logs/provider capacity and budget alerts. Revisit provisional budgets with measured customer inventory and allowed load before launch. No hosted Actions, paid load service or production traffic is needed for this lab.
