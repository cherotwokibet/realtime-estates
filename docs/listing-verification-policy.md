# Private synthetic check records: provisional policy

22 October 2026, checkpoint121. Engineering policy for synthetic fixtures only. It does not establish real identity, advertising authority, ownership, availability, a public verified badge or client policy acceptance. Task06-6 remains open.

Business-rules.md distinguishes moderation approval from independently evidenced verification. The new pure shared contract records what a current company administrator reports checking. Named subjects are identity, advertising_authority and availability. Outcomes supported, not_supported and inconclusive describe the administrator's assessment of the exact recorded note. They are not a platform attestation or a current property state. Each note must be explicit enough for a human to understand the assessment; the validator checks structure, not the factual truth of its prose.

The only accepted policy is `synthetic-check-record-v1`. Evidence references are opaque bounded `synthetic:` identifiers, never URLs, credentials, personal documents or external retrieval instructions. Supported and not_supported require a reference; inconclusive may explicitly use null. The note is untrimmed canonical nonblank text of at most600 Unicode scalars without controls or invalid surrogates. Observed time is an explicit canonical UTC millisecond instant. The contract does not fetch, authenticate, hash or persist evidence bytes. Real evidence storage, rights, access and retention need separate policy and implementation before real use.

An exact original command has operationId, policy, target, expectedVerificationVersion, subject, outcome, evidenceReference, note and observedAt. The target binds listingId, listingVersion, latest revision and revisionVersion. A separate nonnegative verification history version allows the first record at0 and preserves operational listing versions. No caller tenant, actor, role, completion time, verified flag, publication, availability mutation or arbitrary field is accepted.

`planListingVerification` is pure and grants no resource access. It requires independently supplied current admin status, actor, trusted time and current target/history facts. Nonadmin is refused before reading caller command fields. Target currency conflict precedes history-version conflict, then maximum-version, future-observation and regressing-record-clock refusals. Version0 requires no prior record time; a positive history version requires one. Equal recording times are permitted because the separate version still orders records. Old observations are historical facts, not freshness or expiry claims.

A planned immutable record retains the exact original operation, policy, target, assessment, reference, note and observation time, adds the trusted actor and recording time and increments only the independent verificationVersion. It contains no verified boolean and changes no current listing, availability confirmation, public snapshot or publication status. No amount of supported records automatically establishes a public badge. Later corrected assessments must append records rather than edit earlier evidence.

This checkpoint adds only the validator/planner/types and meaningful domain tests. There is no database ledger, API, SDK method, operator form, original-receipt reader or production check recorder yet. Domain tests verify detached frozen snapshots, no listing mutation, all subjects/outcomes, canonical references, exact currency priority, overflow/time refusals, Unicode bounds, forbidden caller authority and accessor refusal. Record validation and durable receipt semantics must be implemented and tested alongside persistence, not inferred from this pure plan.

Next persistence design: current enabled company and active admin authorization before resource existence or stale-fact disclosure; lock target and verification state, then append record, increment the history version, append an attributable audit event and store original receipt atomically. Exact same actor/original operation/facts replay must return its original receipt without new history; changed facts or another actor must not adopt it. Original recovery remains read-only and requires current authorization. A bounded current-admin company history may show historical actors but must never imply their membership is still active. Validate the resulting record/receipt before commit. Test role revocation, cross-company access, stale target/history, replay after later state and atomic rollback before default activation. No real provider, document upload or public badge is part of this provisional policy.

KES10,000 total recurring monthly client price, synthetic-only data boundaries and the old live system remain unchanged. Production identity/providers, asset and data rights, query-cost measurements, retention, legacy RPC retirement, hosted concurrency, device/operator acceptance and cutover remain separate open gates.
