## Server configuration

Both origins are canonical HTTPS origins without path, query, credentials, explicit port or trailing slash. The public applicationOrigin and private apiOrigin must differ. The private target must be a canonical Cloud Run run.app service origin.

The environment additionally requires production NODE_ENV, staging APP_ENV, K_SERVICE, matching GOOGLE_CLOUD_PROJECT and HOSTED_API_INVOCATION_CONFIG with policy cloud-run-invocation-v1 and audience exactly equal to apiOrigin. ## Request and response boundaries

Only GET account, GET favourites (limit1–50 and optional UUID after cursor), GET favourite state and GET/POST favourite operation UUID routes are admitted. Unsupported paths/methods, extra or duplicate query keys, encoded paths, foreign origin and cookie/actor/tenant/company/role/workload/forwarded-authorization headers are refused. There is no staff, signup, deletion, push or general proxy endpoint.

The gateway verifies the Firebase ID token's signature, project/issuer/subject, verified email, nonanonymous provider, time and revocation through the shared strict server verifier before acquiring a Cloud Run service credential. The private API repeats its strict verification and resolves the live authoritative SQL UID-to-actor/company membership binding. The two bearer authorities stay separate: Firebase Authorization identifies the user; server-only X-Serverless-Authorization supplies invocation identity. The actual private HTTP envelope strips routing headers before the customer handler.

Commands are strict duplicate-key-aware JSON capped at2048 bytes and128 chunks; operation ID must match the path. Responses are capped at32768 bytes and128 chunks and validated against maintained exact DTO/company/version/operation contracts. Redirects, cookie-setting/cacheable or malformed/private bodies are refused. Responses contain only validated DTOs or generic error codes with no-store/nosniff headers; upstream diagnostics and headers are not copied. The default deadline is8 seconds (hard configuration maximum15). Cancellation/timeout covers body reading, authority checks, invocation and response reading; late completion cannot start a private request after cancellation. The gateway never retries a POST. Native uncertain-outcome recovery remains original-operation GET, then explicitly identical retry only after a missing-original response.
