## Working path

- API: v2 search now accepts an exact property `id`. Explicitly gated synthetic `GET /v3/properties/search` reuses bounded statement-snapshot count/paging and adds county/locality/neighbourhood/amenity IDs against approved historical attributes. Unknown IDs match nothing; ordinary v2 refuses reference filters. Reference search remains 404 when the existing reference moderation feature is disabled. Caller identity/tenant is not selected by filters. No migration or default reference activation changed.
- Shared client: `searchPropertiesV2` and `searchSyntheticReferencePropertiesV3` take typed filter objects and anonymous request options. Inputs are captured and validated before transport; accessors, unsupported context and bearer tokens are refused. Returned policy/count/limit/offset/order/cardinality/hasMore/maxOffset and public DTOs are validated, duplicate IDs and wrong-ID lookups refused, and results frozen. Reads have no-store/omitted credentials/rejected redirects, bounded 3 MiB streaming and duplicate-JSON-key rejection. No retry or demo fallback was added. The new tests are included in the normal client test script.
- Web: trusted server configuration `WEB_CATALOGUE_SEARCH=public-search-v1`, alongside connected mode, selects the new client contract. Reference mode still needs its existing explicit synthetic development/test configuration. URLs preserve existing filters plus reference IDs, order and page. Twelve-card server pages are not locally sliced again. Counts and pagination use global matching totals; loaded-only mode keeps its existing honest labels. Price order still requires a declared purpose/rental period. Out-of-range results retain their exact totals; offsets over 10,000 are refused before transport. Direct detail lookup uses ID search, so an item beyond the original first 100 records can open. No browser query/header configures API origin or company.
- Mobile: the explicit synthetic reference screen now submits location searches to the API and offers previous/next server pages with exact matching totals. Editing search text does not silently change the applied page; submitting resets offset. Search controls remain available during errors so a bad query can be corrected. Existing effect cleanup aborts superseded requests and prevents late results replacing the current page. Preview contact/enquiry actions remain disabled. The adapter's old bounded read stays available for compatibility; the screen explicitly requests search.
- Preview: the existing independently owned preview router now delegates the new public routes through the same strict search parser. This fixes a real integration gap; an earlier run correctly failed because the preview allowed only the old feed. Trusted company/host/identity guards remain intact.

The mobile integration test compiles the public web adapters explicitly through `@realtor/web`'s new `test:compile` script, rather than relying on stale generated files. The ordinary web test uses the same compile script.

## Limits and acceptance

Web location/amenity dropdown choices still come from the current returned page, with explicit unavailable selections retained. These are not yet exhaustive catalogue-wide facets. This prevents treating task 07-2 as fully accepted even though supplied saved IDs filter the whole catalogue correctly. Existing price filtering is an exact positive maximum on a stated price basis, not an invented all-in affordability quote.

Global totals are from a single SQL statement snapshot per request; separate pages can change as stock changes. Limit 1–100, offset 0–10,000, two-second SQL statement timeout and 3 MiB response bounds remain. The public website uses 12 items/page and mobile uses 24. The screen reports the traversal bound and mobile prompts users to narrow the search when it reaches that bound. These are not end-to-end connection deadlines or hosted load guarantees.
